# Productization Reference

Use this reference when choosing what skill to build, how to position it, or how to connect a free GitHub skill to paid work.

## Good Skill Niches

Choose a niche where the user already pays with time, money, risk, or anxiety.

Strong categories:

- release and deployment checklists
- code review and migration workflows
- compliance or submission packets
- niche documents for a profession
- data cleanup and report generation
- marketplace listing and launch workflows
- customer support triage
- research synthesis with strict source handling

Weak categories:

- generic writing
- generic productivity
- broad "business assistant"
- anything whose output cannot be inspected
- anything that depends on spam, fake accounts, or platform loopholes

## Offer Ladder

Use this ladder:

```text
Free: installable skill that solves one narrow problem.
Low-ticket: templates, examples, checklists, sample inputs, and launch pack.
Mid-ticket: customization for a company, repo, or workflow.
High-ticket: implementation, integration, team training, or maintenance.
```

## GitHub Positioning

The README should answer, above the fold:

1. What does this skill do?
2. Who is it for?
3. What input does it need?
4. What output does it create?
5. How do I install or copy it?
6. What does a good example look like?

Use a concrete example before philosophy.

## Launch Channels

Prioritize:

- GitHub repository with examples
- X/Twitter post
- Hacker News "Show HN" only if the skill is useful to hackers
- Reddit communities only where self-promotion is allowed
- LinkedIn post for professional workflow skills
- niche Discord/Slack communities where you already participate

Do not mass-post the same message everywhere. Rewrite for each audience.

## Pricing Ideas

Avoid selling "the free skill." Sell:

- private version tuned to a business
- repo-specific migration pack
- example library
- managed setup
- monthly updates
- consulting call
- audit report using the skill

## Evidence To Collect

Ask early users for:

- before/after output
- time saved
- confusing install steps
- missing examples
- follow-up tasks they still needed help with

Do not fabricate evidence.
