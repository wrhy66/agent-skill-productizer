# Roadmap

The project should look alive without creating fake momentum. The goal is not constant noise. The goal is a steady trail of useful examples, trustworthy maintenance, and clearer paid customization paths.

## Update Cadence

### Weekly

Small updates that improve conversion or usefulness:

- add one example workflow
- improve one launch post
- answer issues
- tighten README wording
- add one public skill idea from real user feedback

### Monthly

Cut a small release when there is a visible improvement:

- new example pack
- better audit checks
- improved templates
- clearer private-skill offer
- user-requested workflow support

### Quarterly

Review the offer:

- which examples created issues or custom requests
- which channels produced useful traffic
- whether 499 RMB still fits the starter scope
- whether a larger implementation package should be separated

## Versioning Strategy

Use simple semantic versions:

- patch release: docs, examples, copy, templates, audit wording
- minor release: new workflow support, new checks, new reusable templates
- major release: incompatible folder structure or skill behavior changes

Do not release just to look active. Release when the change gives a visitor a better reason to try, star, share, or request a custom private skill.

## Near-Term Priorities

1. Add 3-5 example workflows for buyers who can afford custom work.
2. Improve the request flow for private skill builds.
3. Add proof from real usage only when it exists.
4. Make the audit script more useful for other skill repos.
5. Package a small example pack if repeated requests appear.

## Monetization Notes

The 499 RMB offer should stay narrow:

- one workflow
- clear input
- clear output
- no private integrations
- one revision round

Larger work should be quoted separately as implementation, integration, or team workflow setup.
